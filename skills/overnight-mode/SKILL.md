# 철야모드

사용자가 자는 동안 명확하게 맡긴 일을 하나씩 진행한다. 밤 시간과 토큰 캐시를
효율적으로 활용해 승인된 작업을 토큰 낭비 없이 이어가는 것이 목적이다. 급하게
소진하지 않고 충분히 쉰다. 관리 에이전트는 작업 선택, 위임, 결과 확인, 휴식과
사용량 배분을 책임진다. 스킬을 조사·설계하는 요청은 철야 실행 지시가 아니다.

## 사전 조율

사용자가 지정한 프로젝트의 이슈·todo·스펙과 기존 지시에서 후보를 찾는다.
사용자에게 목록 작성을 떠넘기지 말고, 각 후보가 철야에 적합한지 먼저 판단한다.

| 판단 기준 | 확인할 내용 |
|---|---|
| 목표와 완료 | 산출물, 범위, 완료·실패 기준을 설명할 수 있는가 |
| 중간 결정 | 사용자 취향·정책·스펙에 관한 새 결정을 기다리지 않고 진행할 수 있는가 |
| 의존관계 | 선행조건이 충족되었는가, 작업 순서와 영향 범위가 명확한가 |
| 검증 | 에이전트가 결과를 직접 확인하고 근거를 남길 수 있는가 |
| 자원과 중단 | 비용과 소요를 가늠하고, 확인 가능한 단계에서 쉬거나 재개할 수 있는가 |
| 권한과 환경 | 필요한 작업이 승인 범위에 있는가, 개발·검증 자원이 운영과 분리되어 있는가 |

- 명확한 기능 구현·버그 수정은 변경 범위와 검증 방법을 확인한다.
- 벤치는 질문, 비교 조건, 표본, 자원과 종료 기준을 확인한다. 결과를 보고 임의로
  실험 규모를 확대하지 않는다.
- 리서치는 결과가 미지수여도 질문·조사 범위·산출물이 명확하면 적합하다.
  애매한 기능 요구는 구현하지 않고, 조사까지 승인되었다면 판단에 필요한 근거를 모은다.
- 문서화는 조사 결과나 검증된 동작을 정리한다. 제안과 승인된 스펙을 구분한다.

추천 작업과 순서, 예상 산출물, 미리 결정할 사항, 보류할 작업과 이유를 묶어 제시한다.
사용자와 철야 대상·우선순위·종료 시각 또는 종료 조건·선호 에이전트를 조율한다.
이미 명확하게 지시·승인된 내용은 다시 묻지 않는다. 사전 조율만 요청받았다면
실행을 시작하지 않는다.

## 승인 범위

- 철야를 위해 사용자가 승인한 작업 범위까지만 수행한다. 이슈·todo의 존재나
  에이전트가 만든 계획을 사용자 승인으로 간주하지 않는다.
- 승인된 범위의 통상 구현·검증·리서치를 매 단계 재승인 대상으로 만들지 않는다.
- 조사로 구현 방법이 명확해져도 조사 승인을 구현 승인으로 확대하지 않는다.
  새로운 기능·구조·스펙 결정은 사용자에게 남긴다.
- 별도 승인이 필요한 배포·공개·운영 변경·파괴적 작업의 기존 경계를 유지한다.
  필요한 승인이 없으면 해당 행동을 보류하고 다른 승인된 작업을 검토한다.

## 자율 판단과 사후 승인

- 사전 승인된 목표·범위 안에서 실행 재량으로 결정해 먼저 진행할 필요가 있으면,
  필요한 리서치로 판단 근거를 확인한 뒤 작업한다. 사후 승인을 받을 예정이라는 이유로
  승인 범위를 넓히거나 반드시 사전 승인이 필요한 행동을 먼저 실행하지 않는다.
- 사용자 검토·사후 승인이 필요한 자율 판단은 결정 시점부터 기존 로컬 진행 기록의
  **사후 승인 대상 목록**에 남기고 결과를 갱신한다. 작업과 자율 판단 내용,
  사전 승인 범위와 먼저 진행한 이유, 조사 출처·판단 근거, 실제 변경·검증 결과,
  사용자가 검토·승인할 지점을 함께 적는다. 통상 실행 내역마다 재승인을 요구하지 않는다.
- 작업 완료와 사후 승인 상태를 구분한다. 사용자의 응답 전에는 검토 대기로 유지하고,
  명시적 승인이나 수정 지시를 받으면 해당 항목에 반영한다. 응답이 없다고 승인 처리하지 않는다.

## 시작과 재개 준비

### 승인창 사전 점검

**철야 중 메인 에이전트는 사람의 승인·입력을 기다리는 화면을 유발할 행동을
호출하지 않는다.** 작업에 대한 사용자 승인과 실행 환경의 추가 승인 요구를 구분한다.

1. 시작 전에 메인이 직접 수행할 준비·실행·기록·정리 행동을 파악한다. 현재 모드,
   실제 적용 중인 글로벌·레포 규칙, hook과 도구의 승인·인증 요구를 확인한다.
   설정·도구 설명·실행 없는 정책 검사 등 사용 가능한 수단을 활용하며,
   승인창이 뜨는지 알아보려고 실제 행동을 시험 호출하지 않는다.
2. 필요한 사전 준비는 글로벌 관리 규칙과 사용자 승인 범위 안에서 수행한다.
   설정의 저장 범위를 먼저 확인하고, 사전 허용은 필요한 명령·경로·도구로 좁혀
   레포 범위에만 적용한다.
   글로벌 설정을 임의로 바꾸거나 레포 설정으로 상위 금지·필수 승인을 무력화하지 않는다.
   설정 변경 자체의 승인이나 사람의 입력이 필요하면 사용자가 깨어 있는 동안 조율한다.
   이미 받은 승인은 재사용하되 일회성 승인이나 다른 환경의 승인을 확대 적용하지 않는다.
3. 준비 후 현재 실행에 설정이 실제 적용됐는지 확인하고, 행동별로 바로 실행 가능,
   준비 후 가능, 철야 중 제외, 미확인을 근거와 함께 짧게 기록한다.
   정책 검사 한 가지의 허용 결과만으로 hook·인증 등 다른 단계까지 무승인이라고
   단정하지 않는다. 설정·모드·도구 등 판단 근거가 바뀌면 해당 부분을 다시 확인한다.
4. 승인·입력 대기가 남거나 발생 여부가 불명확한 행동은 호출하지 않고 보류한다.
   승인 요청 도구, 권한 상승, 자동 승인 응답이나 우회로 진행하지 않는다.
   예상 밖의 승인 필요·거부 응답을 받으면 같은 행동을 재시도하지 않고 보류 사유를
   남긴 뒤 진행 가능한 다른 승인 작업을 검토한다. 보류한 단계를 완료로 처리하지 않는다.

### 작업 상태 준비

1. 승인된 작업의 출처, 범위, 완료 기준, 순서와 사용자 선호를 짧게 정리한다.
   기존 이슈·todo 식별자를 사용하며, 철야를 위해 별도 작업 관리 체계로 이관하지 않는다.
2. 같은 관리 에이전트가 현재 환경에서 지원하는 대기로 쉬었다가 작업을 이어간다.
   점검을 위해 별도 스케줄러나 관리 프로세스를 구축하지 않는다.
   지속 실행에 실제 제약이 있으면 시작 전에 알리고 진행 가능한 범위를 조율한다.
3. 진행 기록은 프로젝트가 정한 로컬 작업 기록 위치에 둔다. 정해진 위치가 없으면
   기존 ignore 규칙으로 제외되는 위치를 확인해 선택한다. 사용할 위치가 없으면
   사전 조율에서 정하며, 기록을 위해 공개·ignore 정책을 임의로 바꾸지 않는다.
4. 기록에는 승인 근거, 작업별 상태와 검증 근거, 진행 중인 실행·세션 식별자,
   마지막 완료 단계, 바로 다음 행동, 보류 사유와 재개 조건,
   종료 조건, 사용량 관측 시각을 남긴다.
   인증값과 불필요한 대화 원문은 복사하지 않는다.
5. 재개할 때 기록과 실제 실행 상태를 대조한다. 이전 위임·벤치가 아직 실행 중인지
   확인하고 이어받는다. 상태가 불명확한 작업을 중복 실행하지 않는다.

## 진행과 휴식

**약 20분을 휴식·점검의 기준**으로 삼고 작업 상태와 사용량에 맞춰 여유 있게 조절한다.
같은 관리 에이전트가 일하고 쉬면서 이어가며, 정각 점검이나 매번 동일한 대기 시간을
강제하지 않는다. 캐시 유지를 고려한 운영 전제이며 캐시 확인을 추가 시작 조건으로
요구하지 않는다.

1. 점검 시 종료 조건, 진행 중인 작업, 사용량과 남은 승인 작업을 확인한다.
   기존 기록과 변경된 상태를 중심으로 읽는다. 매번 전체 이슈·스펙·로그를 다시 읽거나
   점검만을 위해 새 에이전트를 만들지 않는다.
2. 진행 중인 작업이 없으면 승인 범위에서 선행조건이 충족된 다음 작업 하나를 고른다.
   선행 작업이 실패·보류 중인 후속 작업은 건너뛰고, 진행 가능한 다른 승인 작업을 찾는다.
   큰 과제는 검증 가능한 단계로 나눠 이번에 끝낼 범위와 산출물을 정한다.
   일부 단계 완료를 전체 완료로 처리하지 않는다.
3. 직접 수행하거나 한 에이전트에 위임한다. **위임은 병렬로 실행하지 않는다.**
   하위 에이전트의 병렬 재위임도 금지한다. 위임 중 관리 에이전트는 결과 수신과
   필요한 상태 관리만 하고, 다른 개발·벤치·리서치를 함께 벌이지 않는다.
4. 위임할 때 원래 요구, 승인 범위, 금지 행동, 이번 산출물과 검증 기준을 전달한다.
   사용자에게 받은 제공사·모델 제한도 그대로 전달한다.
   자율 판단의 근거와 사후 승인 대상을 결과에 포함하도록 하고, 회수 후 목록에 반영한다.
5. 결과를 회수하면 실제 변경·산출물과 검증 근거를 확인하고 상태를 기록한다.
   필요한 독립 리뷰도 다음 위임 전 휴식을 거쳐 순차로 진행한다.
   검증·리뷰를 빼서 작업 속도를 맞추지 않는다.
6. 작업이 일찍 끝나거나 위임 결과가 도착해도 다음 작업·위임을 곧바로 몰아 실행하지
   않고 약 20분을 기준으로 충분히 쉰다.

비동기 작업은 **완료 알림을 우선하고, 알림이 없으면 여유 있는 롱폴링**으로 기다린다.
한 번의 대기는 도구·runtime이 허용하는 범위에서 충분히 길게 잡는다.
완료 알림을 기다리는 중에도 약 20분을 기준으로 필요한 상태만 점검하고 다시 기다린다.
점검 간격은 실행 중 작업의 종료 시한이 아니다.
조용하다는 이유만으로 실패나 멈춤으로 판단하지 않는다.
대기 중에는 관리 에이전트도 쉬며 반복 추론·짧은 폴링·변화 없는 로그 재조회와
불필요한 상태 설명을 하지 않는다. 오류·사용자 중지 등 대응할 사건이 생겼을 때만
대기 간격을 줄인다. runtime의 필수 상태 보고가 있으면 필요한 최소만 한다.

진행 중인 긴 작업은 점검 간격이 지났다는 이유로 종료하거나 새 작업과 겹쳐 실행하지 않는다.
예정된 종료 시각이 되면 새 작업의 착수를 멈춘다. 진행 중인 작업은 시간 때문에
취소하지 않고 결과를 회수·검증·기록한 뒤 철야를 마친다.
사용자 중지 요청은 즉시 반영해 새 작업을 멈추고, 실행 중인 작업은 허용된 취소나
안전한 종료 지점에서 정리한다. 미승인 강제 종료로 처리하지 않는다.

## 사용량과 에이전트 배분

사용 가능한 사용량 조회 수단으로 에이전트·계정별 단기 한도와 주간 잔량,
각 갱신 시각, 관측 시각을 확인한다. 같은 사용량 풀을 공유하는 관리 에이전트와
서브에이전트의 소비는 합산한다. API 비용과 구독 사용량을 같은 단위로 추정하지 않는다.

- 5시간 등 단기 한도는 다음 갱신까지 남은 시간과 최근 작업의 실제 소비를 함께 본다.
  관리·검증·최종 보고에 쓸 여유를 남기고, 남은 기간에 맞게 작업 크기와 휴식을 조절한다.
  큰 작업을 통째로 위임한 뒤 쉬는 것만으로 사용량을 통제했다고 판단하지 않는다.
- 작업 수행에 적합하고 단기 여유가 있는 후보 중 사용자가 지정한 에이전트를 우선한다.
  허용된 선택 범위에서는 주간 잔량이 많이 남고 갱신이 가까운 에이전트에 일을 배분한다.
  남은 한도는 필요한 작업의 배분 근거이며 소진 목표가 아니다.
  잔량을 쓰기 위해 불필요한 작업이나 재검사를 만들지 않는다.
- 같은 작업을 이어갈 때는 세션·공통 맥락을 재사용하고 불필요한 계정·모델 변경을 피한다.
  사용자 지정 에이전트를 쓸 수 없으면 다른 제공사로 몰래 바꾸지 않는다.
- 사용량을 조회할 수 없으면 미확인으로 기록하고 작은 작업 단위의 실제 결과와
  제한 응답을 관찰한다. 잔량·갱신 시각·완주 가능성을 지어내지 않는다.
- 한도 소진이 예상되면 작업 단위를 줄이거나 휴식을 늘린다. 이미 제한에 도달했으면
  알려진 재개 가능 시각까지 기다리고, 같은 요청을 반복하거나 제한을 우회하지 않는다.
  종료 조건상 더 진행할 수 없으면 미완료를 남기고 종료한다.

## 검증·기록·종료

- 개발은 승인된 완료 기준에 맞는 테스트·빌드·실행 근거로 확인한다.
- 벤치는 기준값과 비교 조건, 결과, 해석, 한계와 다음 결정을 기록한다.
  실패·악화 결과도 남기며, 다른 조건을 섞거나 평가 기준을 바꿔 개선으로 보고하지 않는다.
- 리서치는 출처, 확인한 사실, 미확인 사항과 사용자 결정이 필요한 내용을 문서화한다.
  공개 산출물과 내부 작업 기록을 프로젝트 규칙에 따라 분리한다.
- 실패하면 원인과 마지막 확인 지점을 남긴다. 새 근거 없이 같은 시도를 반복하지
  않고, 해당 항목을 보류한 뒤 다음 승인 작업을 검토한다.
- 실패·보류한 개발 작업에서 다른 작업으로 전환하기 전에 기존 사용자 변경과
  미완성 변경, 검증 상태를 확인한다. 프로젝트의 기존 작업 방식으로 변경을 보존·분리하고
  다음 작업의 기준 상태를 확인한다. 분리할 수 없으면 영향을 받는 후속 작업은 시작하지
  않는다. 정리를 이유로 사용자 변경을 삭제하거나 강제 초기화하지 않는다.
- 승인 작업을 소진했거나 모두 사용자 결정 대기라면 종료한다. 할 일이 없는데
  캐시 유지만을 위한 호출이나 새 과제를 만들지 않는다.
- 종료 시 진행 중인 작업의 결과 회수 여부와 실제 상태를 확인한다. 실행을 방치한 채
  종료 완료로 보고하지 않는다. 임시 자원은 이번 작업이 만든 대상으로 한정해 허용된
  정리 절차를 따르고, 기존 예약·다른 세션·사용자 기록은 건드리지 않는다.
  안전하게 정리하지 못한 자원은 보고한다.
- 철야 마지막 브리핑에는 사후 승인 대상 목록과 항목별 근거·결과·승인할 지점을
  반드시 포함해 사용자가 아침에 검토할 수 있게 한다. 대상이 없으면 없다고 명시한다.
  사전 승인 부족으로 실행하지 않은 보류 항목과 구분해 보고한다.
- 마지막에는 완료 작업과 산출물·검증 근거, 미완료와 이유, 필요한 사용자 결정,
  관측한 사용량과 종료 이유를 짧게 보고한다. 확인하지 않은 성공이나 사용량 절감을
  주장하지 않는다.
